The Bug, the Audit, the Blueprint

It started with a wrong CSS class name. It ended with an instruction layer that any AI can walk into cold. Here is how four collaborators — one human, two Claude instances, and an external AI reviewer — built something none of them could have built alone.

What this was

In June 2026 I asked for an audit of cameronloudon.github.io — my personal brand site built on Jekyll and GitHub Pages. The immediate trigger was a bug: a CSS class name used in the site's collaboration notes was wrong in one session log. I wanted to know what else was wrong.

The audit found more than a bug. It found a workflow that worked well as long as the same AI was always in the room — but had no documented path for a different AI to pick up the project. My site attributed AI collaboration openly, under the Radical Collaboration Transparency framework, but the AI infrastructure itself was neither transparent nor transferable.

Three weeks and six phases later, the site has an instruction layer: a set of plain-text files at the repo root that any capable AI can read, cold, and use to orient itself — without asking me to explain anything, without access to session history, without knowing what Claude or Cowork are.

This is the full account of how that happened.
