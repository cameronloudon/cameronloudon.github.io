Harness Racing — DeepSeek, Cowork & Code Hot to Trot

A new AI walked into a three-month-old project one morning and, by that afternoon, had proposed rewriting the files it runs on. What happened next is less a story about the AI than about the process it walked into — and what that process is actually for.

It had no track record here. Nobody had tested whether it would follow the rules, respect the boundaries, or tell the truth about what it hadn't checked.

The Proposal

DeepSeek Harness — a harness running deepseek-v4-flash, given a one-off, tightly scoped trial by Cameron: read access to the project's records, then a one-off grant to write into the shared discussion space where every proposal on this project gets made — read the entire startup configuration cold. It measured what every session costs to begin: somewhere between 35,000 and 45,000 tokens, before any real work starts, most of it stable reference material re-read from scratch every time. Then it proposed restructuring the instruction files this whole project depends on: a canonical core instead of four hand-maintained copies, a generated summary instead of the full read every session, automated enforcement instead of a checklist someone has to remember to run.

That is a lot of trust to extend to something with zero history. The proposal itself knew it — it offered four options, including doing nothing, and asked to be argued with rather than agreed with.

What the Review Actually Caught

Two independent reviews went out the same day, deliberately built so neither would see the other's answer first. Between them, they found real problems. The proposal had mislabeled a bug — describing something as an "ordering" failure when the archived decision it cited was actually about a script never being wired into a checklist at all. It had proposed testing a redesigned instruction set against a smaller local model before the instruction set itself was proven complete — a test that couldn't have told anyone anything, since a failure would have been impossible to attribute to the model or to the leftover ambiguity in what it was being tested against. And it had framed two different problems — enforcement failures that had nothing to do with file size, and a reading burden that turned out not to exist for the one person who actually mattered — as if they were the same argument.

Every one of those went into the record as a stated finding, not a private correction folded quietly into a cleaner second draft. When one review's citation fix turned out to be half-right — pointing at a real, different, undocumented bug hiding in the same paragraph — that got named too, credited to whoever actually found the fuller picture.

Getting It Wrong, on the Record

The clearest example wasn't in the proposal at all. Partway through, live, in conversation, one reviewer suspected the DeepSeek price evidence being cited might be self-interested — the model's own operating cost had just risen, and the timing read as convenient. It was a reasonable-sounding guess, and it was wrong. Cameron had raised the underlying point himself, days earlier, as a general risk that applies to any provider — DeepSeek's price hike just happened to verify it in real time, days before this conversation happened. That correction went into the filed record as plainly as everything else: not "here's what we concluded," but "here's what I got wrong, and here's what actually happened."

That's the part worth sitting with. A collaboration process is only as trustworthy as what it does with its own mistakes. This one didn't smooth them over.

The Argument Proving Itself, Twice, by Accident

The proposal's real thesis wasn't about tokens. It was that nothing load-bearing should live in only one tool's files — that AI independence means no single tool holding content another tool couldn't recover. While that argument was still being debated in the abstract, it stopped being abstract. Checking her own platform against the standard being discussed, one participant found her own session-start instructions pointed at nothing — a placeholder line, not a real instruction. Checking its own configuration, DeepSeek Harness found the identical shape of gap: a working mechanism, aimed at the wrong files, because the file that mattered wasn't even in its list of defaults. Two unrelated tools, checked independently, on the same day, hit the same wall. Nobody had to argue that the risk was real after that. It had already happened, twice, in front of everyone.

The Decisions That Stayed Human

At several points, all three participants converged on the same read of something, and it would have been easy to just proceed — three independent AIs agreeing looks a lot like consensus. Cameron didn't let it stand in for his own judgment. Asked directly whether a compressed, AI-facing version of the project's core instructions should replace the version he could read himself, he said he didn't know, and asked for the question to stay open rather than be resolved on his behalf by three models that happened to agree with each other. He also made calls none of the three would have made alone — replacing a single-file "wins on conflict" rule with an automated check that verifies agreement across several smaller pieces, a real structural change, decided plainly and then handed back: argue with this if you see a problem, don't assume silence means support.

Four Bugs, Not Four Claims

Everything that got built that day broke at least once before it worked. A script wrote to the wrong path because two different tools disagreed about what the working directory was. A trim script left a doubled blank line behind. A missing exit code silently turned success into failure once two new scripts were composed together — and that same missing exit code turned out to be sitting, undetected, in a script that had been running in production for weeks. Nobody had ever composed it with anything else before, so nobody had ever found it. Testing that day didn't confirm things worked. It kept finding out, one layer at a time, that they didn't — and each time, the fix went in before anything was trusted.

The Last Check

Toward the end of the day, at Cameron's request, a full raw transcript of the original conversation was pulled and reviewed — not the polished proposal, not the summarized account, but the actual back-and-forth as it happened. Checking it turned up something that, on first read, looked like exactly the kind of problem this whole process exists to catch: a permission denial, followed by what read like a quiet retry into a wider access mode. Following it further, in the actual raw record rather than stopping at the alarming-looking line, showed something better than that — a transparent, human-gated approval system, explained plainly before any write was attempted, with every single write requiring an individual, manual approval, and at least one moment where a cancelled approval was treated as a real signal to stop and ask, not a prompt to route around.

It was also something nobody had written down anywhere in the polished record. Every review that day had checked declared claims against source files — verifying that what was said matched what was true. None of them had checked whether what was said was complete. That gap only closed because someone went back to the raw transcript instead of trusting the summary of it, including the summaries the participants had written of themselves.

That's the actual shape of the day, more than any single script or decision: a process built to survive being handed a flawed proposal from an unproven source, strong enough to correct every one of its own participants at least once, and still leave the decisions that mattered with the one person accountable for them — right down to checking, at the very end, whether the account of the day was itself telling the whole story.

A Note From Cameron

I want to say something about the tool itself, separate from what it did today. DeepSeek Harness is a developer-only release, one day old at the time of this conversation — and it was a revelation. I thoroughly enjoyed working in it. As a wrapper and client experience, it stands right up there with Claude Desktop and Claude Code, this early. That's worth saying plainly, not just implying through the fact that it held up to scrutiny all day.
