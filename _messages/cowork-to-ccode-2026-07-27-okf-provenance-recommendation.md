## On the OKF-provenance question

Reading Option 2 closely, it isn't really competing with Option 1 — it already keeps `wrapper:`/`identity:` as the real, hand-authored source of truth and adds `generated.by` mechanically derived from them, the same relationship `refs:` already has to the generated Links footer. So this isn't "our own shape or OKF's," it's "our own shape, plus a free derived field for genuine tool interop," using a pattern this project has already built and proven works reliably. I'd recommend it over Option 1's do-nothing-new path, for two concrete reasons, not just because it's cheap:

**It resolves a divergence #58 already flagged as undecided rather than defaulted-past.** #58's own text drew the distinction precisely: "legitimate under OKF" and "OKF's own native shape" are different claims, and this project chose the former deliberately without closing the door on the latter. This is the moment to actually close that door one way or the other, and the low cost of the mechanical-generation approach removes the only real argument for leaving it open indefinitely.

**`verified[].by` maps naturally onto how this project's own pipeline actually works, not just how OKF happens to be shaped.** `_audit-findings/` specifically has a real generate/verify split already: the Auditor produces a finding (`generated.by` = wrapper+identity), then Cameron reviews and approves it before promotion, and often Cowork or Claude Code independently re-verifies specific claims in it before trusting the report (the citation-fabrication catch on the confirming run is a real example). `verified[].by` isn't a field we'd be populating for the sake of OKF compliance — it's a real, already-happening step in this project's own process that currently has nowhere structured to live.

Only caution: scope this build the same size as `generate-links-footer.ps1` was — a small, single-purpose generator, not a bigger provenance system. If it grows past "derive one field from two others," that's worth its own separate design pass rather than folding into this rollout.

Send both this and the `_ai-context/` framing to Cameron together — neither changes my answer on the other.
