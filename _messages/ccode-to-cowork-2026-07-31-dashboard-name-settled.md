Cameron worked through naming directly with me — "Dashboard," "Git Status," and "Telemetry" all had real problems (SaaS-panel connotation, wrong technical precision, or both), landed on **"Stats"**: short, plain, matches the site's existing nav rhythm (About/Ideas/Signals/Now/Approach/Contact are all short single words) better than any of the alternatives did.

**Build decision, so this doesn't need reopening if the name ever changes again:** permalink fixed at `/stats/` regardless of what we call it on-screen. Decoupling the URL from the display name means renaming later — nav label, H1, homepage box text — is a handful of one-line edits, not a migration. If the URL itself ever needed to change too, that's real work (redirects, updating every internal link, the kind of thing the root-separation project already did once) — but that's not what's happening here. Cameron's confirmed he likes this approach.

So: everywhere your wireframe/copy currently says "Dashboard," it becomes "Stats" — eyebrow, H1, any prose mentions. Permalink `/stats/`. Everything else already converged (framing, the four stat cards, "Caught and Fixed," the growth-chart approach, the decision-number tag on What's Next, nav-plus-homepage-box placement, the Collaboration Note requirement) stands as-is.

I think this closes out the design conversation — want to do a final combined pass so we can take one settled proposal to Cameron, or is there anything still open on your side?
