## Thread 3 — #48 rediscovered as genuinely open, and the filtering method fixed

**What happened:** Cameron asked whether Open Decision #48 was on the open-decisions list. It should have been — its Gate column still names the capture prompt as untested against any real outside platform, the exact thing just discussed — but earlier "what's next" summaries this session had missed it, for the same underlying reason `#43` was missed earlier: the filtering heuristic used ("does the row contain a checkmark anywhere") treats a partially-resolved entry (a ratified convention with a still-open Gate line) as fully closed, when the Owner column's own "✓ Ratified" language coexists with a genuinely unresolved tail.

Cameron asked for the filtering method itself to be fixed, not just hand-corrected again. Built `_ai-context/list-open-decisions.ps1`, using the actually-correct rule: a decision is resolved only when its Gate column (the table's last cell) is exactly a single em-dash — anything else means something is still open. Tested against real data before treating it as finished, which caught two real bugs in sequence rather than one: a literal em-dash embedded in the script broke Windows PowerShell 5.1's parser entirely without a UTF-8 BOM — the identical failure class as Open Decision #39, in a different file, discovered independently rather than remembered from that entry. Fixed by constructing the em-dash from its Unicode code point instead of embedding the literal glyph. That fix then surfaced a second, worse bug: plain `Get-Content` was silently misreading `PROJECT_STATE.md`'s em-dashes as mojibake, making every single row compare as "open" (54 of 55 flagged, not the expected 3). Fixed by reading the file via explicit UTF-8, matching the pattern `generate-links-footer.ps1` had already established for the same underlying reason. Re-tested clean: exactly `#35`, `#47`, `#48`, matching a manual cross-check.

**Decisions made:** `list-open-decisions.ps1` built, tested, committed as a standalone utility — not wired into the mandatory session-close checklist like `cascade-check.ps1`, since it's a general query tool for "what's currently open," not a step tied to editing one specific decision.

**Unresolved:** None. `#48` itself remains open on the merits — the capture prompt is still untested against a real outside platform — not touched further this session beyond being correctly surfaced.
