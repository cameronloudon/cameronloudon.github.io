## Thread 3 — `generate-provenance.ps1` built, proactively avoiding a known bug class

**What happened:** Built the derivation script mirroring `generate-links-footer.ps1`'s structure: reads `wrapper:`/`identity:` frontmatter, emits/refreshes a marked `generated.by:` field (`human:<id>`, lowercased/hyphenated, for `wrapper: Person`; `<wrapper>/<identity>` literally otherwise), skips files with neither field (expected for nearly everything, forward-only), fails loudly with a specific missing-field message if only one of the pair is present. While writing the report-summary counts, recognized the same shape of expression (`(...).Count` on a `Where-Object` result) that caused a real, previously-documented bug twice already in this project (`cascade-check.ps1`'s `$Matches`-clobbering, and the identity-backfill script's false 0-auto-fill result) — both from a PowerShell 5.1 quirk where a single-item match returns `$null` instead of `1`. Fixed proactively with `@(...)` array-context wrapping and a comment citing the precedent, rather than waiting to hit it a third time.

**Decisions made:** No `verified[].by:` in this build — named in the schema doc as a good future fit, explicitly out of scope per Cowork's own scoping caution (keep this the same size as `generate-links-footer.ps1`).

**Unresolved:** `verified[].by:` — named, not designed, tracked in `attribution-schema.md` §4.
