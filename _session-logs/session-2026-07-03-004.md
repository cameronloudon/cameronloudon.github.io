## Thread 1 — Missing index-page entry found live on production

**What happened:**
Cameron reported the newly-published `_ideas/four-agent-collaboration-test/` page was not showing on `https://cameronloudon.github.io/ideas/`. Investigation confirmed the page itself was live and rendering correctly (GitHub Pages had rebuilt fine, no frontmatter or Jekyll collection problem) — but `_ideas/index.html` is a hand-written static list of `<li>` entries, not a Jekyll loop over `site.ideas`. Nothing in `AI_INSTRUCTIONS.md`, `ai-content-creation-spec.md`, or `rct-validation-checklist.md` documented updating this list as a required publishing step, so it was silently skipped during the four-agent-collaboration-test publish (session-6). `signals.html` (repo root) was confirmed to have the identical pattern — also a static list, not generated.

**Decisions made:**
- Added the missing `<li>` entry for `four-agent-collaboration-test` to `_ideas/index.html`, matching the existing entries' structure and using the page's actual metadata (date, tags, excerpt).
- Documented this as a required step in `ai-content-creation-spec.md` §6, directly after the ideas entry template.
- Added a new item to `rct-validation-checklist.md` §2 (Content Integrity) plus a reviewer note, so future publishes catch this before merge rather than after Cameron notices it live.

**Unresolved:**
None. Same shape of gap as the session-8 branch-staleness fix: a required step that existed in practice but was never written down, so no agent — human-directed or automated — had a way to know it was needed except by noticing the site looked wrong afterward.
