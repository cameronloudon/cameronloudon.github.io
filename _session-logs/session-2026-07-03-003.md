## Thread 1 — Closing the recurring PROJECT_STATE.md branch-staleness bug

**What happened:**
During the four-agent-collaboration-test live run (OpenCode as Publish Agent, sessions 5 through 7, documented in `session-2026-07-03-002.md`), the same bug recurred three separate times: `PROJECT_STATE.md`'s Active Branch section named a branch that had already been merged into `main`. Each time, it was caught only because Claude Code was independently cross-checking OpenCode's claims against real git state (`git status`, `git branch --show-current`, `git log`) during the test — not because the documented workflow required it. After the session-7 fix, the exact same thing happened again immediately: `PROJECT_STATE.md` said `session-7 (current session)` while `session-7` was already merged via PR #31.

The root cause was structural, not a one-off execution mistake: `AI_INSTRUCTIONS.md`'s session-start ritual instructed reading `PROJECT_STATE.md` but never instructed verifying its Active Branch claim against actual git state. Since the Publish Agent's role ends at push and Cameron merges afterward in a separate action, the Active Branch section is only ever true for the brief window before merge — every session start was liable to inherit stale state unless someone happened to check by hand.

**Decisions made:**
- Added a mandatory verification step to `AI_INSTRUCTIONS.md` §2 (session-start ritual): cross-check `PROJECT_STATE.md`'s Active Branch claim against `git status` / `git branch --show-current` / `git log` before doing anything else, and correct the file immediately if stale.
- Mirrored a shorter pointer in `CLAUDE.md`'s Branch Workflow section, directing back to `AI_INSTRUCTIONS.md` §2 as the canonical version.
- Corrected `PROJECT_STATE.md`'s own stale `session-7` reference to `session-8` as part of doing this fix — applying the new rule to itself in the same session.

**Unresolved:**
None. This closes the recurrence going forward. It does not retroactively change the three prior instances, which remain accurately documented in `session-2026-07-03-002.md`.
