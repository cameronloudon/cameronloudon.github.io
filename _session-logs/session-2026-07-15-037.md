## Thread 2 — generate-provenance.ps1's Second Correction

**What happened:** Closing #48 required substantively editing `decisions-archive.md`. Running last session's just-shipped fix on it afterward revealed a real gap, caught directly rather than by re-review: the guard skipped recomputing `at:` whenever `by:` already matched current `wrapper:`/`identity:` — but the same author (Claude Code) editing the same file's real content twice leaves `by:` unchanged, so the guard silently missed a genuine edit and left `at:` stale at the previous edit's date. None of last session's five test scenarios covered this exact case.

Proposed two automatic-detection alternatives to Cowork: a commit-diff walk (find the last commit that changed more than just the `generated:` line) and a content hash (skip only when a fingerprint of the file minus its `generated:` line is unchanged). Cowork identified the actual deciding factor: diff-walk fails *confidently wrong* if it ever misjudges a commit as `generated:`-only when something else also changed — worse than staleness for a field whose whole job is being a trustworthy record — where a content hash fails safely, just boringly (an unnecessary but still-true recompute). She proposed a third option: explicit signal, no automatic detection at all — a file with `generated:` already present is always left alone unless named via a new `-ForceRestamp` parameter — matching a pattern this project already uses repeatedly (`role: not applicable` stated rather than blank, `stage:` as an explicit marker). Presented all three options to Cameron directly; he picked explicit signal ("go with option 3").

Cowork caught two real process gaps in the same thread, both before any building happened: first, that Cameron's exact words on the option choice were never quoted in the visible record, only asserted by Claude Code — relayed as a direct quote to close the gap. Second, that his approval of the *design direction* wasn't the same as approving the *finished diff* — every other change today got a separate "do you approve committing this" on the finished result, and this one shouldn't skip that step just because the philosophy fork was already settled. The actual diff and six-scenario test plan were then presented to Cameron separately, and approved.

**Decisions made:** Built the explicit-signal guard — a file with `generated:` present is always skipped unless named in `-ForceRestamp`, applying uniformly including a genuine `wrapper:`/`identity:` edit (no longer auto-detected) and a malformed `generated:` line (left alone by default, not auto-fixed — Cowork's reasoning: fixing it unasked would be exactly the inference this correction exists to eliminate). Tested against six synthetic scenarios in a fresh sandbox repo: fresh stamp, already-stamped-not-forced (the actual regression case — confirmed byte-identical via `git status` despite a genuine same-author content edit), already-stamped-forced, an unrelated new file in the same batch, a malformed line not forced, and a malformed line forced. Then ran against the real 557-file `_messages/` bundle with no `-ForceRestamp` at all — zero writes, confirmed via `git status`. Committed. Also hand-corrected `decisions-archive.md`'s own stale `at:` value directly, since the correct value was already known, ahead of the script fix landing.

**Unresolved:** None on the fix itself — verified against both synthetic scenarios and the exact real-world case that exposed the first fix's gap.
