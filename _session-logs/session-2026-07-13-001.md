## Thread 2 — Reading-discipline tangent, rejected under the AI-Independence filter

**What happened:** Cameron asked whether `PROJECT_STATE.md` needs to be read in its entirety, drawing an analogy to HTML anchor links. Established that plain markdown has no equivalent — GitHub's `#anchor` links are a rendering-layer, human-navigation feature only; a raw file read pulls the whole file regardless. Proposed a reorder-plus-marker convention ("Open items at top, stop reading below this line unless searching") as a workaround. Cameron then applied the AI-Independence lens directly: does this depend on retrieval sophistication a weaker or simpler tool might not have? It does — a tool without partial-read capability, or one that doesn't reliably honor a "stop here" instruction, gets no benefit at all. Rejected as a *primary* fix on that basis; a smaller file is smaller for any tool regardless of sophistication, which is what pushed the recommendation back toward A specifically (byte reduction) over reading-discipline tricks.

**Decisions made:** Marker/reorder idea dropped as the primary mechanism. AI-Independence confirmed as a real, load-bearing filter on this specific decision, not just a stated value — concrete evidence for whatever standing-filter proposal comes later.

**Unresolved:** None.
