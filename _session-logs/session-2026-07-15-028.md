## Thread 2 — Open Decision #61 Resolved: Manual Check, Then a Real Build

**What happened:** Cameron asked to look at #61. Presented its current text plainly, then — per his direct request — ran the manual completeness check before any build decision, rather than deciding on the strength of "nothing has actually gone missing, as far as anyone's checked." Cross-referenced all 514 real `_messages/` files against every entry link in `index.md`: zero missing. Real result: currently clean, the risk named in #61 was real in principle but hadn't yet manifested.

Cameron asked what the check had actually done, confirming it was cheap — a plain directory listing plus a single-file grep against `index.md` itself, never touching the content of any of the 514 individual message files. That cost profile directly informed his decision: "cheap enough to run at every session close without it being a real token expense — lets build it."

Built `_ai-context/check-messages-index-completeness.ps1`, mirroring the manual check's own method but hardened against the false-positive trap discovered during that manual pass — entry links matched only on real list-item lines (`^\s*-\s*\[`), not any `[Title](./file.md)`-shaped text anywhere in the document, so the format-description prose can never be misread as a dangling reference. Tested against real data first (matched the manual check exactly, 514/514 clean) and then against a synthetic fixture built in an isolated temp folder, covering both failure modes (a file missing its entry, an entry pointing at nothing) plus the false-positive trap explicitly — all three confirmed correct before being trusted.

Given Cameron's own stated reasoning was specifically about session-close cost, wired the new check into the actual Session-Close Protocol checklist in both `CLAUDE.md` and `AI_INSTRUCTIONS.md` — mandatory at every close, not conditional on `_messages/` having changed, matching his words rather than a narrower interpretation. Also added it alongside `function-b-state-check.ps1` in `backlog-promotion-workflow.md`'s own verification step, since batch promotion is exactly where a missing entry would most likely originate.

Ran `cascade-check.ps1 -DecisionNumber 61` before archiving, per the mandatory rule — all four surfaced candidates were incidental tool-name overlaps or already-correct historical pointers, nothing required an edit. Archived #61's full text verbatim to `decisions-archive.md`; stubbed the row in `PROJECT_STATE.md`.
