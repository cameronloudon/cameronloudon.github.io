## Thread 2 — Recurring PROJECT_STATE.md staleness: root cause and structural fix

**What happened:** Cameron asked why `PROJECT_STATE.md` keeps going stale and whether the process should prevent it from staying stale once he's confirmed a merge. Verified the specific instance directly: `main` HEAD was `65cc2ef` (merge of PR #33, session-9) with a clean working tree, but `PROJECT_STATE.md` still named `session-9` as the current Active Branch, branched from `baec9cb` — one merge behind. Checked the AI-Prod mirror too; not a git repo, byte-identical to the stale repo file, no independent signal.

Root cause identified: the Active Branch field is written once, when a session pushes its branch, and is only invalidated by an event — the merge — that happens later on GitHub with no AI session present to react to it. The existing fix for Open Decision #19 (session-start git-state verification) is reactive: it only runs if and when some session happens to start, which could be long after the merge, or might get skipped. The project already has a defined, reliable trigger for the merge moment — Phase 2 — AI-Prod Sync, fired by Cameron pasting the GitHub merge-confirmation message — but its documented steps only covered the AI-Prod robocopy sync, never `PROJECT_STATE.md`.

**Decisions made:** Phase 2 now corrects `PROJECT_STATE.md`'s Active Branch immediately, before the AI-Prod sync, by checking out `main`, pulling, and creating the next session branch right away — pushing that correction as a normal commit on that branch, not a direct-to-`main` exception. That branch then becomes the starting point for whatever the next real task turns out to be, rather than a branch being created fresh (reactively) once that task starts. Added the CLAUDE.md-specific version (with the git/robocopy commands) and a general, tool-agnostic version in `AI_INSTRUCTIONS.md` §6, cross-referenced from §2's existing verification-ritual text. Applied the fix immediately to the actual stale state found: corrected Active Branch from `session-9` to `session-10` (this session), branched from the true current `main` HEAD.
